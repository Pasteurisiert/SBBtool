System Architecture & Mathematical Specification: Swiss Multi-Modal Transit Optimization Engine

1. Executive Summary & Regulatory Framework

This specification provides a mathematically rigorous, deterministic, and audit-proof foundation for the Swiss Public Transport Connection & Topology Visualisation Engine. The platform interfaces with the Swiss Federal Open Data Transport API [1], providing passenger and timetable routing over multi-modal networks including standard-gauge rail (SBB, BLS, SOB), metre-gauge networks (RhB, MGB), municipal transit (VBZ, BVB, Bernmobil), and regional postbuses (PostAuto).

To comply with Swiss Federal Office of Transport (BAV) regulations and operational dispatch guidelines [2], the engine separates passenger journey evaluation into three deterministic phases: corridor discovery, directional kinematic transfer reconciliation, and Pareto-optimal path selection across multiple conflicting objectives.

2. System Architecture & API Data Contract

The underlying transport network is queried via the REST service /v1/connections [1]. Each requested query tuple $\mathcal{Q} = (v_{\text{orig}}, v_{\text{dest}}, T_{\text{ref}}, \mathcal{M})$ returns an ordered set of raw journey candidate objects.

3. Topological Stop Normalisation & Footpath Synthesis

Multi-modal railway junctions allocate distinct terminal identifiers between railway platform tracks and adjacent municipal bus loops (e.g. Baden, DiDok 8503504 vs. Baden, Bahnhof West, DiDok 8503505) [1]. If the provider payload fails to return an explicit walk object between consecutive differing station entities, topological continuity is ruptured.

Let incoming section $e_i$ terminate at stop $u \in V$ at timestamp $T_{\text{arr}}(e_i)$, and outbound section $e_{i+1}$ originate from stop $w \in V$ at timestamp $T_{\text{dep}}(e_{i+1})$. Where $u \neq w$, the normalisation operator $\Omega_{\text{norm}}$ synthesises an explicit pedestrian edge:

$$\begin{equation} e_{\text{walk}} = \big(u,\, w,\, \Delta t_{\text{walk}}\big), \quad \Delta t_{\text{walk}} = \frac{T_{\text{dep}}(e_{i+1}) - T_{\text{arr}}(e_i)}{60\,000\,\text{ms}\cdot\text{min}^{-1}} \end{equation}$$
Dimensional verification: $[( \text{ms} - \text{ms} ) / (\text{ms} \cdot \text{min}^{-1})] \equiv [\text{min}]$

To prevent distortion in subsequent transfer rankings, physical walking legs are strictly decoupled from vehicle interchange counts [3]:

$$\begin{equation} N_{\text{veh}}(k) = \max\left(0,\, \Big| \{ e \in E(k) \mid \text{isJourney}(e) = \text{true} \} \Big| - 1 \right) \end{equation}$$
Dimensional verification: Pure dimensionless integer count $[-]$

4. Nodal Headway Verification & Cascading Rescheduling

Interchange reliability is governed by the Swiss infrastructure standard MINUST (Mindestumsteigezeiten) [3]. For each junction node $v \in V$, an individual persistent threshold $\tau_{\text{min}}(v)$ is defined and loaded from client-side persistent storage $\mathcal{S}(v)$ [4].

The available operational transfer buffer $\Delta t_{\text{buffer}}(v)$ is evaluated against $\tau_{\text{min}}(v)$:

$$\begin{equation} \Delta t_{\text{buffer}}(v) = \frac{T_{\text{dep}}(e_{i+1}) - T_{\text{arr}}(e_i)}{60\,000\,\text{ms}\cdot\text{min}^{-1}} \ge \tau_{\text{min}}(v) \end{equation}$$
Dimensional verification: $[\text{min}] \ge [\text{min}]$

Whenever $\Delta t_{\text{buffer}}(v) < \tau_{\text{min}}(v)$, the forward or backward trajectory is broken, invoking the recursive rescheduling cascade $\mathcal{T}_{\text{repair}}$:

$$\begin{equation} \mathcal{T}_{\text{repair}}(P_k, v) = \begin{cases} (e_1, \dots, e_i) \cup \mathcal{Q}_{\text{fwd}}\left(v,\, v_{\text{dest}},\, T_{\text{arr}}(e_i) + \tau_{\text{min}}(v)\cdot 60\,000\right) & \text{if } \mathcal{M} = \text{dep}, \\[1em] \mathcal{Q}_{\text{bwd}}\left(v_{\text{orig}},\, v,\, T_{\text{dep}}(e_{i+1}) - \tau_{\text{min}}(v)\cdot 60\,000\right) \cup (e_{i+1}, \dots, e_m) & \text{if } \mathcal{M} = \text{arr}. \end{cases} \end{equation}$$
Dimensional verification: Millisecond timestamps $[\text{ms}] \pm [\text{min}]\cdot[\text{ms}\cdot\text{min}^{-1}] \equiv [\text{ms}]$

Convergence is guaranteed by bounding recursion depth to $N_{\text{iter}} \le 6$, preventing infinite cyclic dispatch under tight timetable headway scenarios [5].

5. Multi-Criteria Pareto Optimization with Proximity Tie-Breaking

Candidate itineraries $\mathcal{K}$ are evaluated across three conflicting scalar metrics: total travel duration $J_{\text{time}}$, number of vehicle interchanges $J_{\text{trans}}$, and cumulative distance-tariff equivalent $J_{\text{cost}}$ [6]:

$$\begin{equation} J_{\text{time}}(k) = \frac{T_{\text{arr}}(e_{\text{last}}) - T_{\text{dep}}(e_1)}{60\,000\,\text{ms}\cdot\text{min}^{-1}} \quad [\text{min}] \end{equation}$$ $$\begin{equation} J_{\text{cost}}(k) = \sum_{e \in E(k)} \Big( \alpha \cdot \Delta t(e) + \beta \Big) \quad [\text{CHF}], \quad \alpha = 0.4\,\text{CHF}\cdot\text{min}^{-1}, \; \beta = 2.0\,\text{CHF} \end{equation}$$
Dimensional verification: $[\text{CHF}\cdot\text{min}^{-1}\cdot\text{min} + \text{CHF}] \equiv [\text{CHF}]$

To align with passenger intent, ties within any category are broken by selecting the candidate whose terminal schedule boundary lies closest to the user-specified reference timestamp $T_{\text{target}}$:

$$\begin{equation} \delta_{\text{prox}}(k) = \begin{cases} \dfrac{\big| T_{\text{dep}}(e_1) - T_{\text{target}} \big|}{60\,000\,\text{ms}\cdot\text{min}^{-1}} & \text{if } \mathcal{M} = \text{dep}, \\[1em] \dfrac{\big| T_{\text{arr}}(e_{\text{last}}) - T_{\text{target}} \big|}{60\,000\,\text{ms}\cdot\text{min}^{-1}} & \text{if } \mathcal{M} = \text{arr}. \end{cases} \end{equation}$$
Dimensional verification: Absolute time deviation $[\text{min}]$

The lexicographic selection operator $\prec_{\text{opt}}$ yields the three winning profiles:

$$\begin{equation} k^*_C = \arg\min_{k \in \mathcal{K}} \Big( J_C(k),\, \delta_{\text{prox}}(k) \Big) \quad \forall C \in \{\text{time}, \text{trans}, \text{cost}\} \end{equation}$$
Dimensional verification: Lexicographical order over tuple $([\text{dim}_C],\, [\text{min}])$

6. Stratified Visualisation & Rasterised Itinerary Generation

The winning Pareto paths are visualised as independent, vertically stratified horizontal lanes in SVG space [7]. For route index $r \in \{0, 1, 2\}$ and leg sequence index $j \in \{0, \dots, m\}$, node coordinates are defined deterministically:

$$\begin{equation} X_{r, j} = X_0 + j \cdot \Delta X, \quad Y_{r, j} = Y_0 + r \cdot \Delta Y_{\text{lane}} \end{equation}$$
Dimensional verification: Pixel offsets $[px] = [px] + [-]\cdot[px]$, with $\Delta X = 380\,px, \; \Delta Y_{\text{lane}} = 220\,px$

To prevent typographic interference between route metadata headers and initial stop labels, a minimum orthogonal bounding box clearance is enforced:

$$\begin{equation} Y_{\text{header, bottom}} < Y_{\text{node, top}} - \Delta Y_{\text{clearance}}, \quad \text{with } \Delta Y_{\text{clearance}} = 29\,\text{px} \end{equation}$$
Dimensional verification: Length inequality $[px] < [px] - [px]$

For external archiving, the timetable schedule is projected into an auxiliary DOM document without vector graph elements. Itinerary boundaries $T_{\text{dep}}(e_1)$ and $T_{\text{arr}}(e_{\text{last}})$ receive high visual contrast styling before being rasterised to a 24-bit RGB JPEG bitstream via HTML5 Canvas supersampling at scale $\mu = 2.0$ [8].
